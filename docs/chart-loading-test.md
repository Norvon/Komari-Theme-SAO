# 图表加载测试版

测试包：`Komari-Theme-SAO-N-v1.1.7-test.1.zip`。

## 调整范围

- 负载和 Ping 查询共用 30 秒总预算，WS、HTTP 和 records 回退不会分别重新计时。
- HTTP 401/403 不再触发 records 回退或请求层自动重试，详情图表显示登录或权限提示。
- Ping 详情曲线先返回，统计和公开任务名称独立补齐；辅助请求失败时使用曲线样本统计和任务编号。
- 首页 Ping 不再等待公开任务列表；预热缓存或批量统计提供名称，缺失时临时显示任务编号。
- RPC 失败日志补充方法、时间范围、耗时和错误信息，不输出完整请求参数或凭据。
- 保留多线路不限 8 条以及新增的历史时间档位。

## 站点验证

1. 登录后分别打开负载和 Ping，测试 1 小时、30 天、90 天，记录 Network 中 RPC 请求耗时和曲线出现时间。
2. 模拟统计或任务列表响应慢，确认 Ping 曲线先出现，名称和统计随后更新。
3. 快速切换节点和时间范围，确认旧统计不会覆盖新范围；刷新失败时，同一范围已有曲线仍保留。
4. 私有站点退出登录后，确认 401 不会继续请求 records，详情页给出登录提示。
5. 阻断 WS 后确认可用 HTTP 仍能加载；整个查询超时后停止回退，可手动重试。

本地受控延迟与自动化测试不能替代登录后站点实测。若 HTTP 查询本身慢，仍需排查服务端查询和代理链路。

## 本地受控计时

环境：macOS arm64、Node v26.5.0。使用实际 API 适配代码、单条 Ping 样本和模拟 RPC，以真实计时器分别注入延迟。对照组保留原来的合并等待方式，测试组使用详情页的分离请求方式。

| 模拟条件 | 合并等待：曲线数据就绪 | 分离请求：曲线数据就绪 |
| --- | --- | --- |
| 曲线 10ms、统计 500ms、任务列表 10ms | 503.49ms | 12.00ms |
| 曲线 10ms、统计 10ms、任务列表 500ms | 501.70ms | 11.51ms |

这些是单次受控样本，只验证辅助请求不再阻塞曲线；不包含真实网络、服务端数据库或浏览器绘制耗时，也不是线上提速比例。
